RAG · OBSIDIAN · MCP · PYTHON

Useful AI memory, without drowning agents in context.

Hybrid retrieval, sanitized ingestion, decoupled publishing and cross-agent handoffs: retrieval is only as trustworthy as its sources.

PUBLIC CODE + PRIVATE MEMORYSources reviewed 21/10/2026

retrieved ≠ true

01 / THE PROBLEM ISN'T SOLVED BY VECTORS

The problem isn't solved by vectors

An agent loses immediate context when sessions change. Sending entire folders and conversations every time floods the context window, slows responses and surfaces stale material. Meanwhile, retrieving a document does not independently prove it is correct.

I approached the problem in two parts: find a small amount of relevant evidence, and prevent an agent's unverified inference from silently becoming a canonical fact.

02 / HOW INFORMATION TRAVELS

How information travels

Public vault-mcp combines lexical and vector retrieval with reciprocal rank fusion (RRF). A note graph provides outgoing links, backlinks and unresolved references. An agent can request a targeted brief rather than receiving complete archives.

In parallel, convia-sanitize handles conversation exports: track changes, redact secrets, keep originals separately and emit durable requests for downstream RAG publication. The publisher is decoupled from the sanitizer so failed delivery does not blindly repeat mutations.

llm-wiki extracts sources, concepts and entities from unstructured notes and validates consistency with lint rules. Its chunking responds to tokens-per-minute quotas (TPM), not a claim of improved model context-window use.

03 / READING AND WRITING ARE DIFFERENT PRIVILEGES

Reading and writing are different privileges

Retrieval is non-mutating. New facts or corrections go through write intentions, explicit permissions, consent and conflict checks. The Vault is the durable source, while the RAG index exists to find it.

Within the private memory layer, observations, user statements and inferred claims are tracked separately. An agent's suggestion is not independently verified just because it appears more than once. Compact handoffs convey decisions, constraints, provenance and current state, not entire transcripts.

04 / A USEFUL DOCUMENTATION DISCREPANCY

A useful documentation discrepancy

One public README described CouchDB as its upstream mirror, while a different RAG branch documents a synchronized notes mirror, incremental indexing and periodic reconciliation. That difference is itself a documentation-quality issue. Without a fresh production inspection, I do not claim either README perfectly describes today's live topology.

05 / EVIDENCE AND LIMITATIONS

Evidence and limitations

The public repositories expose retrieval, policy, sanitization and lint implementation. Private notes remain private. No token-efficiency or retrieval-precision improvement is claimed without measured, comparable benchmarks.

06 / DESIGN DECISIONS

Four architecture decisions

RRF + graph

Combine exact matches and semantic similarity while preserving provenance.

Intents + consent

Keep writes separate from retrieval and subject to permissions and conflict checks.

Just-in-time context

Load the current project's brief, not entire conversation archives.

Resilient ingestion

Treat rate limits and remote failures explicitly instead of masking them as success.

07 / LIMITS

Evidence, limits and open measurements

NO INVENTED GAINS

A documented memory-audit protocol is not proof every cycle ran. Secret redaction is best effort, never perfect anonymization. Retrieval evaluation needs ground-truth answers, not just agreement between two indexes.
