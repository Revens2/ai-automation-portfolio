PROJECTS/ SANDBOX

RUST · QEMU · MCP · ISOLATION

Let an AI execute code without surrendering the host.

A bounded MCP sandbox built around disposable VMs and explicit, measurable isolation trade-offs.

PRIVATE CASEReviewed on 21/10/2026

exit 0 ≠ verified

01 / THE INITIAL RISK

The initial risk

Agents sometimes need to run untrusted code or inspect unfamiliar files. Granting that code direct access to the host mixes trusted data, privileges and untrusted execution.

The design goal was a disposable execution environment that does not inherit the primary machine's credentials or filesystem mounts.

02 / HOW IT WORKS

How it works

An OAuth-protected MCP interface exposes a fixed set of task tools. A broker delegates work to a runner responsible for disposable QEMU Linux sessions and a small guest-side agent.

The permitted operations are bounded: launch approved argument vectors, read paginated output, transfer limited files, cancel tasks and destroy sessions. Unknown tools are denied.

03 / DECISIONS AND TRADE-OFFS

Decisions and trade-offs

Guests do not receive host secrets or privileged mounts. Network access and session lifetimes are constrained. Tasks are passed as validated argv instead of arbitrary shell strings.

The referenced ARM64 environment did not expose KVM acceleration, so QEMU used TCG emulation. That performance cost is a real compromise, not something to hide behind a general claim of virtualisation.

04 / THE SUBTLE DISTINCTION

The subtle distinction

A program can return exit code 0 while producing the wrong answer. The protocol separately represents process_succeeded and objective_verified. Execution success and business-goal success are distinct properties.

05 / EVIDENCE AND LIMITATIONS

Evidence and limitations

The detailed implementation is in a private repository. The existing Excalidraw illustration shows its conceptual architecture. This is not a security certification or a performance benchmark.

06 / ENGINEERING

Three choices that matter

Disposable VM

Contain untrusted execution and discard the guest after use.

Limited MCP surface

Explicit scopes and bounded file sizes, duration and arguments.

Honest compromise

Use TCG when hardware KVM acceleration is unavailable.

07 / NEXT

What remains to be proven

EXPLICIT LIMITS

Valuable follow-ups include isolation testing, comparable TCG/KVM benchmarks, and cleanup/concurrency fault injection.
