Watchy: ship a real product, then investigate discoverability.

From React and PostgreSQL to sitemaps and Search Console: building a product means checking the code, the data and external behaviour.

PRIVATE CASEOpen investigation · 2026-10-21Reviewed on 21/10/2026

HTTP 200 ≠ indexed

01 / THE PRODUCT

The product

Watchy brings movie, television and anime tracking into an installable web application. Users can import viewing history, find ongoing series, track upcoming episodes and explore statistics.

The architecture combines React 19 and Vite on the client, Fastify on the backend, Prisma and PostgreSQL for persistence, and Docker for deployment. Metadata comes from multiple public services.

02 / HOW IT WAS BUILT

How it was built

An imported or searched title moves from an external data source through API-side normalization into application storage. The PWA fetches typed application data and renders search, watchlists, calendars and statistics. Existing screenshots show real app screens, not generated mockups.

Mobile installation, caching, catalogue reconciliation and timestamp consistency introduce distinct engineering concerns beyond the visible UI.

03 / WHY SEO BECAME AN ENGINEERING CASE

Why SEO became an engineering case

A catalogue page can load for a browser while remaining difficult for search engines to crawl. On October 21, 2026, Google Search Console still showed failed sitemap retrieval at its previous fetch, even though current independent browser checks received valid HTTP and XML responses.

Historical server errors during crawling and a significant change in sitemap inventory were additional observations. None demonstrated that Googlebot's issue was already resolved or established its precise cause.

04 / HOW THE INVESTIGATION PROCEEDED

How the investigation proceeded

I separated four evidence types: Search Console status, direct HTTP checks, available GA4 observations and merged GitHub changes. Each is dated. A browser response today cannot cancel out an earlier crawler error.

The next steps are to compare sitemap generations, verified crawler logs and robot-specific responses, then observe a fresh Search Console read. Private traffic metrics are not reproduced here.

05 / STATE OF THE CASE

State of the case

Investigation open as of October 21, 2026. The available signals do not establish one proven root cause. Positive application health checks are not equivalent to guaranteed uptime or successful search indexing.

06 / DECISIONS

Three engineering decisions

Pragmatic stack

Installable React PWA, Fastify API, Prisma and PostgreSQL in containers.

Separate measurements

GA4 sessions, sitemap entries and GSC impressions are not interchangeable.

Diagnosis before claims

Do not present a fix as validated without new crawler evidence.

07 / LIMITS

What remains unproven

TRANSPARENCY / 2026-10-21

Private codebase and audit reports. Screenshots show product features, not adoption or uptime. The crawling root cause remained unproven on October 21, 2026.
