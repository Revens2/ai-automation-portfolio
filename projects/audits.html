AUDIT · GITHUB · RAG LINT · GA4 / GSC

Audit without confusing hypotheses, observations and outcomes.

Code review, knowledge quality and SEO share a rule: missing evidence must never silently become success.

PUBLIC CODE + PRIVATE AUDITSReviewed on 21/10/2026

observed ≠ proven

01 / WHY INDEPENDENT CHECKS MATTER

Why independent checks matter

An agent can finish a change without verifying quality. Crawlers can fail when a product looks healthy in a browser. A RAG index can be populated yet inconsistent. Audits exist to test these disagreements, not to manufacture green status.

02 / CASE ONE: SEMANTIC PR REVIEWER

Case one: semantic PR reviewer

Public pr-reviewer polls explicitly allowlisted GitHub repositories. It deduplicates by repository, pull request and head commit, then runs a read-only source snapshot inside an isolated Docker worker.

A structured verdict is published as an advisory GitHub status. PASS requires model identity certification; failures and uncertainty cannot silently turn green. Advisory review is not a protected merge gate.

Semantic review complements, rather than replaces, deterministic CI checks such as tests, Semgrep and Gitleaks. Pull-request code is untrusted input, not an instruction source for the model.

03 / CASE TWO: RAG QUALITY LINT

Case two: RAG quality lint

Public llm-wiki includes rule-based linting (R1–R24) for knowledge structure and references. Incremental ingestion handles quota failures and resumability. Successful indexing does not independently prove the knowledge is consistent or true.

04 / CASE THREE: WATCHY SEO INVESTIGATION

Case three: Watchy SEO investigation

Internal reports combine Search Console, GA4, direct HTTP responses and merged code changes. An October 21 report documented differences between earlier Google sitemap-read status and recent successful browser requests, along with incompatible windows and unavailable data.

That does not validate a fix: the root cause remained unproven. The useful output was testable hypotheses and prioritized checks, rather than a convenient invented explanation.

05 / MAKING A CONCLUSION

Making a conclusion

The final audit distinguishes directly observed facts, plausible inferences, evidence still needed and prioritized next steps. Unavailable data is labelled unavailable, never automatically zero.

Audit value depends on traceable evidence and improved decisions, not the number of issues an LLM claims to detect.

06 / DECISIONS

Three engineering decisions

Bounded reviewer

Advisory model, isolated from write privileges on reviewed code.

Independent layers

Deterministic checks, AI review and external observation remain distinct.

Visible unknowns

Unmeasured is not zero and not validated.

07 / LIMITS

What remains unproven

TRANSPARENCY / 2026-10-21

No benchmarked error-detection rate or audit performance claim. Watchy reports remain private. Advisory reviews do not enforce merges; structural lint does not certify corpus truth.
