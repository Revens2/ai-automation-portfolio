agent-orchestrator-mcp

Let a ChatGPT Web session dispatch coding missions to local agents — without exposing a shell.

ChatGPT WebVPS brokerWindows runnerClaude Code · Codex · AGY · OpenCode

Problem

A web chat assistant has no safe path to local development tools, and giving it remote shell access is not acceptable.

Architecture

A broker on a VPS receives MCP calls from ChatGPT Web and relays structured missions to a runner on a Windows machine, which drives Claude Code, Codex, AGY or OpenCode.

Engineering points

  • OAuth 2.1 on the MCP endpoint
  • Allowlists for agents and workspaces
  • Mission lifecycle with explicit validation
  • No shell exposed to the model

sandbox-mcp

Disposable Linux VMs that agents can use through MCP, under a fail-closed policy.

MCP clientOAuth + policyRemote runnerQEMU VM (isolated)

Problem

Agents need somewhere to run code, but the host running them must not be the place where that code executes.

Architecture

An OAuth-protected MCP server applies policy, then hands tasks to a remote runner that boots throwaway QEMU virtual machines with network isolation.

Engineering points

  • Fail-closed policy: denied unless allowed
  • Tasks passed as bounded argv, not shell strings
  • Network isolation of the guest
  • VMs discarded after use

ARION

Local 3D reconstruction from Meta Quest captures.

RGB · depth · posesValidationConversionAlignmentReconstruction → PLY / COLMAP

Problem

Headset captures contain colour, depth and pose data, but turning them into usable 3D output requires a reliable, repeatable pipeline — run locally.

Architecture

A staged pipeline: capture validation, format conversion, alignment, then reconstruction, exporting PLY point clouds and COLMAP-compatible data.

Engineering points

  • Inputs validated before any processing
  • Explicit stages that can be checked independently
  • Standard outputs usable in existing 3D tooling
  • 23 tests in the current pipeline

Watchy

Full-stack product to track films, series and anime, installable on iOS and Android.

React 19 PWAFastify APIPrisma · PostgreSQLDocker

Problem

Viewing history is scattered across platforms; users want one place to track and analyse it on any device.

Architecture

React 19, Vite, Tailwind, TanStack Query and Recharts on the client; Fastify, Prisma and PostgreSQL on the server; shipped with Docker.

Engineering points

  • Imports from multiple platforms
  • PWA installable on iOS and Android
  • Statistics and charts on viewing history
  • Typed data access through Prisma
